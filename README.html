Quick start

From a clone of this repository, run:

./setup.sh

With no options, the script copies .bashrc, .vimrc, and the Gruvbox theme; backs up any files it will replace; installs micromamba, the stable Rust toolchain (rustc and Cargo) via rustup, GitHub CLI (gh), Docker Engine, the Docker CLI, Buildx, and the Compose plugin; initializes micromamba for Bash; then prints Docker build/run/exec commands for the agent container and copies them to the clipboard when supported.

The installer supports Ubuntu and Debian only. It needs network access, apt, and root privileges or sudo. Package installation may prompt for your sudo password. Rust and micromamba are installed for the current user; only system packages use sudo.

Choose what to run

./setup.sh --copy-only

Copy dotfiles without installing packages.

./setup.sh --setup-only

Install and initialize the tools without copying repository dotfiles. Micromamba initialization still updates the current user’s ~/.bashrc.

./setup.sh --no-backup

Run the default copy-and-setup flow, but replace destination files without backing them up. This flag can also be combined with --copy-only; it has no effect with --setup-only.

./setup.sh --sv /workspace/mirror "$HOME/path/to/my/dir"

Run the default flow and print Docker commands that bind-mount the host directory at /workspace/mirror in the agent container. The generated commands create the host directory if it does not exist. Only that directory is shared; writes and deletions there affect the host. Ensure it is writable by the container’s dotfiles user. This prints commands without launching Docker; mounts must be specified when a new container is created.

./setup.sh --help

Show all options. --copy-only and --setup-only cannot be used together. --sv accepts an absolute container path and a host directory; paths cannot contain commas or newlines.

Backups & safety

By default, before replacing a destination file, the script saves it under a unique, timestamped directory in:

~/.dotfiles-backups/

For example, an existing .bashrc is preserved at ~/.dotfiles-backups/<timestamp>.<unique-suffix>/.bashrc. The script prints the exact backup directory. If no destination files exist, it creates no backup directory. Existing unrelated Vim files and plugin directories are left alone; only the tracked Gruvbox theme is copied.

Use --no-backup to skip this step entirely. Existing files are then replaced without a recovery copy.

The installer adds the official GitHub CLI and Docker package repositories, installs micromamba from its official download endpoint and Rust via the official rustup installer, and reports errors rather than silently continuing. Rustup selects the stable toolchain, providing rustc and Cargo in ~/.cargo/bin. The installer does not remove conflicting pre-installed Docker packages; if it detects any, it stops and asks you to remove them manually. It also does not add your account to the docker group: membership grants root-equivalent privileges. Use sudo docker ... unless you have deliberately chosen to grant that access.

Try it in a disposable Ubuntu container

The included Dockerfile creates an Ubuntu 24.04 container with Vim and Copilot CLI installed, plus a regular user with passwordless sudo for package setup. To print Docker host commands without installing packages on the host, run:

./setup.sh --copy-only

Run the printed commands on the Docker host. The script also copies them to the clipboard when supported. To create a container with a shared directory, pass --sv:

./setup.sh --copy-only --sv /workspace/mirror "$HOME/path/to/my/dir"

Then run the generated Docker commands on the host. The image has no SSH server and does not run a Docker daemon; starting one would require a separate privileged Docker-in-Docker configuration and is intentionally out of scope. The mounted directory is the only host directory shared with the container, but the agent can change or delete its contents.

Authenticate Copilot from inside the container with copilot and /login. Authentication is not performed during image build.

When finished, leave the shell and remove the container:

exit
docker rm -f dotfiles-agent

To verify Vim inside the container, run vim, then enter :echo g:colors_name. It should print gruvbox. If you previously built the container, rerun the generated docker build command (optionally with --no-cache) and recreate it.

After setup

Start a new Bash session (or run source ~/.bashrc) to load the copied settings and micromamba hook. Open Vim and confirm that Gruvbox loads:

vim

On a regular Ubuntu/Debian host, Docker’s package scripts generally start the service when systemd is available. If needed, start it with sudo systemctl enable --now docker. The daemon will not start in the included test container. Manage Vim plugins separately; this repository tracks only the current color scheme and Vim settings.

Verify the Rust toolchain with rustc --version and cargo --version.
